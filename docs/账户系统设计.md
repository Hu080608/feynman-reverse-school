# 用户账号体系设计

## 技术栈
- 前端：静态 HTML + CSS + 原生 JavaScript（GitHub Pages）
- 后端：Cloudflare Worker
- 存储：Cloudflare KV
- 密码：Web Crypto PBKDF2-SHA256，随机盐，80,000 次迭代
- 会话：随机 user session token，KV 保存，默认 30 天

## 分层
- 路由：`cloudflare/worker.js` 的 `handleRequest`
- 控制器：`handleUserRegister`、`handleUserLogin`、`handleUserLogout`、`handleUserMe`、`handleUserProfileUpdate`、`handleUserChangePassword`
- 服务/安全：`hashPassword`、`verifyPassword`、`createUserSession`、`getUserByToken`、`buildProfileTags`
- 数据：KV keys
  - `user:id:<userId>`：用户记录
  - `user:name:<normalizedUsername>`：用户名唯一索引
  - `user:session:<token>`：登录会话
- 前端：`account.html`、`js/account.js`、`css/account.css`

## 接口
- `POST /api/user/register`
- `POST /api/user/login`
- `POST /api/user/logout`
- `POST /api/user/me`
- `POST /api/user/profile`
- `POST /api/user/password`

## 安全
- 用户名唯一性通过 `user:name:<normalized>` 索引校验
- 密码 PBKDF2-SHA256 + 随机盐，不存明文
- 修改密码递增 `passwordVersion`，旧 session 全部失效
- 所有用户资料接口都校验 user session
- 注册/登录接口按 IP 限流
- 输入长度、枚举值、年龄范围均有校验

## 账号与激活权限绑定
- 登录后激活新码：`/api/redeem` 带 `userToken`，Worker 会把 `user:license:<userId>` 指向新激活 session。
- 换设备登录：`/api/user/login`、`/api/user/me` 会返回 `licenseToken` 和 `licenseStatus`。
- 前端账号页收到 `licenseToken` 后，自动写入主程序 localStorage 的 `backendToken`，设置页和对话页直接使用该账号的学习额度。
- 未登录时仍保留 `clientId` 设备回退逻辑，兼容旧用户。
